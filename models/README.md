# Production model artifacts

Two kinds of thing live here, and neither is generated data in the sense `AGENTS.md`
section 15 keeps out of source control.

## `production/`

One directory per promoted model version, written by `ffdraft train-production`:

```
production/<model_version>/
  metadata.json          # spec, training seasons, feature contract, library versions, hashes
  boosters/*.txt.gz      # one LightGBM text model per group, component and quantile level
```

**No pickles.** Loading a model reads JSON and LightGBM's own documented text format, so
inference never executes a serialized object graph. `gunzip` returns something a human can
read, and `metadata.json` records a SHA-256 per booster, so a regenerated model is checkable
against the committed one rather than assumed to match. An altered booster fails closed.

**Size.** The promoted architecture fits two components x five quantiles per position and
scoring preset — a hundred and twenty boosters, about 45 MB of text and 15 MB gzipped. That
is a lot for one directory and it is the reason the text is compressed at all. Phase 7 owns
the retention policy for repeated retrains: a promoted model *replaces* the previous
directory rather than accumulating beside it, and how many historical versions are worth
keeping is a decision that phase should make deliberately rather than by default.

`metadata.json` records the Phase-2 feature schema hash *and* the Phase-3 core feature-set
hash, and `ProductionModel.assert_compatible` refuses to serve a frame whose contract
disagrees. A model quietly consuming a renamed feature set is the failure this exists to
make impossible.

These artifacts are committed. They are small, they are the only way a build months from now
can reproduce a published number, and `PRD.md` section 15 requires everything needed for
deterministic inference to be versioned.

## `cards/`

Generated by `ffdraft model-card`:

- `intrinsic-<version>.{md,json}` — the model card `docs/MODELING.md` section 22 requires;
- `tier-method.{md,json}` — why the tier boundaries are trustworthy enough for a draft sheet.

Both are **generated from the committed experiment reports and the model artifact**, never
written by hand, for the same reason `docs/FEATURE_DICTIONARY.md` is generated: a number in
a card that no command produces is a number that can drift.

Regenerate after a retrain:

```bash
uv run ffdraft model-card --git-sha "$(git rev-parse --short HEAD)"
```
